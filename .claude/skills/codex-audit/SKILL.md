# codex-audit

## Overview
Получить независимый аудит документа (план реализации, ТЗ, FR) от внешней модели через локальный `codex` CLI. Обёртка `bin/codex-audit` запускает `codex exec` в **read-only** песочнице с корнем в репозитории, так что Codex может сверять утверждения документа с реальным кодом. Результат: нумерованный список замечаний в markdown.

Порядок после аудита: по каждому пункту либо согласиться и внести правку в документ, либо аргументированно не согласиться. **Спорные пункты выносить пользователю на арбитраж (AskUserQuestion), не решать молча.** Codex склонен к оверинжинирингу: предложения «добавить ещё одну систему, слой, очередь» оценивать скептически и при сомнении тоже выносить пользователю.

## The command

```
.claude/skills/codex-audit/bin/codex-audit --file <doc.md> [--focus "на что смотреть"] \
                [--context <path> ...] [--out <findings.md>] [--timeout 900]
```

- `--file`: аудируемый документ (обязательно).
- `--focus`: акценты аудита (например: «безопасность данных, гонки, пропущенные сценарии»).
- `--context`: дополнительные файлы, которые Codex должен прочитать (ТЗ, смежные FR). Можно повторять.
- `--out`: куда сохранить замечания. По умолчанию рядом с документом, `<doc>.audit.md`. Для FR принято `docs/feature-request/N/audit-K.md`.
- Последняя строка stdout при успехе: `OK <path-to-findings>`.

## How to run

1. Запускай через Bash с `run_in_background: true`: аудит длинного документа занимает 3-10 минут.
2. По завершении прочитай файл с замечаниями.
3. Разбери каждый пункт: **согласен**, тогда правка в документ; **не согласен или похоже на оверинжиниринг**, тогда AskUserQuestion с кратким изложением позиций.
4. Итог разбора запиши в журнал аудитов плана (какие пункты приняты, какие отклонены и почему). Файл замечаний оставь рядом с FR.

## Prerequisites
- Рабочий бинарь `codex`. Обёртка ищет его в PATH, затем внутри десктоп-приложений ChatGPT и Codex на macOS. Принудительно: env `CODEX_AUDIT_CODEX_BIN`.
- Авторизация: `~/.codex/auth.json` (при ошибке авторизации пользователь запускает `codex login`).
- Глубина рассуждений: env `CODEX_AUDIT_REASONING` (по умолчанию `high`).

## Common mistakes
- Запуск в foreground: блокирует основную работу на минуты.
- Прогон без `--context` на документе, который ссылается на ТЗ или другие FR: Codex будет гадать вместо проверки.
- Слепое принятие всех пунктов: аудитор не знает продуктовых решений владельца. Сверяй замечания с решениями D и Q в FR, прежде чем «чинить».
