# Шаблон проекта для агентской разработки

На этом шаблоне я собираю свои проекты с Claude Code. Сложной системы внутри нет. Есть папка документов, правила для агента и обычный менеджерский цикл: задача, решения, исполнение, приёмка.

Автор: Андрей Богомолов.

## Идея

Код пишет агент. Человек ведёт проект: ставит задачу, принимает решения и принимает работу. Всё, о чём договорились, записано в файлах репозитория, поэтому в новой сессии агент знает о проекте столько же, сколько вы.

Три правила:

1. **У каждой задачи свой документ (FR)**, в нём решения владельца. Агент не додумывает за вас, а спрашивает, и ответы попадают в документ.
2. **Опасные действия только с согласия.** Удаление файлов и деплой в прод агент сначала согласует.
3. **Фича готова, когда проверена и описана.** Тесты, живая проверка в браузере или на устройстве, обновлённая документация.

## Быстрый старт

1. Создайте проект из шаблона: кнопка **Use this template** на GitHub или
   ```bash
   git clone https://github.com/bogomolovandrey/vibecoding-project-template.git my-project
   cd my-project && rm -rf .git && git init
   ```
2. Откройте папку в Claude Code (`claude`). Правила лежат в `AGENTS.md`, `CLAUDE.md` это ссылка на него, поэтому шаблон работает и с Codex, и с Cursor.
3. Попросите агента настроить шаблон под проект:
   > Прочитай AGENTS.md и docs/README.md. Я хочу сделать: _идея в двух-трёх предложениях_. Задай мне вопросы про стек и окружение, потом заполни раздел «Проект» в AGENTS.md и каркас docs/ARCHITECTURE.md.
4. Заведите первую задачу:
   > Вот ТЗ: _текст_. Заведи FR-1 по шаблону, положи ТЗ дословно в assets и задай мне вопросы по всему, что неоднозначно.
5. Ответьте на вопросы и скажите «делай». Дальше агент работает по циклу ниже.

Как выглядит заполненный FR, показано на выдуманном проекте в [`docs/feature-request/0/`](docs/feature-request/0/0-example-reminder-time.md). Когда заведёте свой первый FR, эту папку можно удалить.

## Цикл одной задачи

| Шаг | Кто | Что получается |
|---|---|---|
| 1. ТЗ | вы | задача в любом виде: сообщение, заметка, скриншоты |
| 2. FR | агент | `docs/feature-request/N/N-slug.md`, ТЗ дословно в `assets/`, вопросы к вам |
| 3. Решения | вы | ответы становятся решениями D1, D2…; где вы промолчали, агент берёт значения по умолчанию Q1, Q2… |
| 4. Аудит | Codex | второе мнение по FR или плану (`codex-audit`), по желанию |
| 5. Разработка | агент | ветка `feature/fr-N-slug`, коммиты `FR-N: …` |
| 6. Проверка | агент | тесты, живой прогон через Playwright или на стенде, данные в БД |
| 7. Закрытие | агент | раздел «Реализация» в FR, обновлённый `ARCHITECTURE.md`, хвосты в `TODO.md` |

К большой задаче (деньги, новая внешняя система, работа на несколько сессий) добавляются исследование, план по этапам и аудиты. Подробно: [`docs/feature-request/README.md`](docs/feature-request/README.md).

## Что внутри

```
AGENTS.md            # правила для агента; CLAUDE.md это ссылка на него
docs/
  ARCHITECTURE.md    # как устроен проект; агент обновляет после каждой фичи
  TODO.md            # бэклог и хвосты закрытых задач
  feature-request/   # как вести FR, шаблоны, пример
  test-plans/        # тест-план: инварианты и каталог точек отказа
  contracts/         # контракт между частями системы
.claude/skills/
  codex-audit/       # аудит FR или плана внешней моделью (Codex), только чтение
  generate-images/   # картинки для экранов в едином стиле (OpenAI Images API)
```

Ревью кода делайте встроенными командами Claude Code: `/code-review` и `/security-review`.

## Что установить

- [Claude Code](https://docs.claude.com/en/docs/claude-code)
- Playwright MCP для проверки интерфейса: `claude mcp add playwright npx @playwright/mcp@latest`
- Для `codex-audit`: Codex CLI и `codex login`
- Для `generate-images`: ключ OpenAI в `.env` (см. `.env.example`)
